# AgentOS Release Hardening

Canonical path: `docs/release-hardening.md`.

## Target Conclusion

Phase 100: Release Hardening does not add runtime capability. It turns the
long-running review branch into a reviewable, publishable, and maintainable SDK
release candidate by requiring a release hardening gate with concrete release
candidate evidence.

The SDK-owned release evidence is:

- public API audit
- stable API and experimental API inventory
- machine-readable public API inventory at `docs/public-api-inventory.json`
- API stability classification
- machine-readable release evidence template at `docs/release-evidence.example.json`
- generated local release candidate evidence at `docs/release-evidence.json`
- release evidence validator:
  `validate_release_evidence_manifest`,
  `ReleaseEvidenceValidationReport`, and
  `RELEASE_EVIDENCE_REQUIRED_GATES`
- migration index
- README / quickstart / examples alignment
- `CHANGELOG.md`
- full test suite evidence
- diff/commit hygiene
- boundary scan evidence for `QueryLoop` and `AsyncQueryLoop`

AgentOS does not run CI/CD, signing, publishing, deployment approval. Those are
deployment-owned release operations. The SDK owns the evidence format,
documentation, reference commands, release gate checklist, and
machine-readable release evidence manifests. The example manifest is
non-certifying SDK evidence and a schema template. The actual release candidate
evidence manifest is generated by a release run, ignored by git, and points at
the immutable source commit that was tested and reviewed. Pending or unknown
gates are intentionally not treated as passed. Neither manifest is a production
certification, deployment approval, signing record, or publishing record.

The release evidence validator is an SDK-owned machine-readable gate over
existing evidence. `validate_release_evidence_manifest` checks that
`RELEASE_EVIDENCE_REQUIRED_GATES` are present and passed, that pending or
failed independent review blocks release-candidate promotion, and that
`ReleaseEvidenceValidationReport` redacts secret-like values from validation
payloads. It does not execute the test suite, run backend probes, sign
artifacts, publish packages, or approve deployment.

## Release Hardening Gate

A Phase 100 release candidate passes the release hardening gate only when every
item below has evidence in the branch:

| Gate item | Evidence |
|-----------|----------|
| Release scope | `docs/release-scope.md` describes the first production SDK release. |
| API stability | `docs/api-stability.md` classifies stable API and experimental API surfaces. |
| Public API inventory | `docs/public-api-inventory.json` records selected public exports, stability classes, and current signatures. |
| Release evidence template | `docs/release-evidence.example.json` records the machine-readable schema with placeholders and non-certifying SDK evidence. |
| Actual release evidence | Generated `docs/release-evidence.json` records actual release candidate evidence, current gate status, commands, evidence refs, and verification timestamps without placeholders. It is intentionally ignored by git so it can point at the tested commit instead of self-referencing its own committed hash. |
| Release evidence validator | `src/agentos/release.py` validates the manifest, fails closed on missing/pending/failed required gates, and applies secret-like value redaction. |
| Public API audit | `uv run pytest tests/architecture/test_public_api.py -q` passes. |
| Migrations | `docs/migrations/README.md` lists schema/data migrations and migration ownership. |
| README alignment | `README.md` links release scope, readiness, API stability, migration index, quickstart, and examples. |
| Quickstart alignment | `docs/quickstart.md` names supported release shapes and links release gates. |
| Examples alignment | `src/agentos/examples/` includes runnable examples with `if __name__ == "__main__"`. |
| Changelog | `CHANGELOG.md` records Phase 96 through Phase 100 release work. |
| Tests | `uv run pytest -q` provides full test suite evidence. |
| Diff hygiene | `git diff --check` provides whitespace evidence. |
| Runtime boundary | Search confirms planner/A2A/team/worker/state-plane/readiness/sandbox/release-hardening concepts are not moved into `QueryLoop` or `AsyncQueryLoop`. |

The boundary scan should produce no matches in `QueryLoop` or `AsyncQueryLoop`.

## Release Boundary

The first production SDK release supports trusted tools, internal service
orchestration, terminal agent, single-node web agent, distributed web agent,
team/planner/A2A primitive composition, production state plane, readiness
evidence, and audit evidence.

Sandbox / Docker / E2B / microVM / enterprise runner adapter work is a
non-blocking future adapter. The release does not promise physical isolation
for untrusted code execution. Production specs must choose one sandbox posture:
`trusted tools only`, `deployment-owned isolation`, or `future adapter`.

## SDK-Owned And Deployment-Owned

SDK-owned release evidence:

- protocols and public API exports
- machine-readable public API inventory and signature evidence
- readiness and audit evidence shape
- machine-readable release evidence manifest
- release evidence validator and validation report
- reference state plane composition
- reference live backend probe invocation plans
- migration documentation index
- stable/experimental API classification
- docs, quickstart, examples, and changelog alignment

Deployment-owned release operations:

- CI/CD execution and approval policy
- artifact signing and publishing
- production deployment approval
- Kubernetes, systemd, autoscaling, tenant directory, and secret distribution
- backend credentials, migration execution, alerting, runbooks, rollout, and rollback
- physical isolation for untrusted code execution
